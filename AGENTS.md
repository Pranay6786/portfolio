## Project rules

- This is a personal product management portfolio for Pranay Patil, targeting APM and Junior PM roles.
- Never add a production dependency without explicit approval. The six current ones are `next`, `react`, `react-dom`, `@mdx-js/mdx`, `gray-matter` and `remark-gfm`.
- No backend, no database, no API routes, no authentication, no analytics, no animation library, no icon library, no state management library.
- All portfolio copy lives in `content/`. Do not hardcode portfolio copy into components.
- Copy rule: use hyphens, never em dashes.
- Never invent research findings, metrics, user numbers, testimonials or outcomes. All content is supplied by the author.
- Preserve existing functionality unless a change explicitly requires modifying it.
- Priorities, in order: maintainability, accessibility, responsive design, performance.
- Record every significant build decision in `BUILDLOG.md`.
- All colours come from tokens. No raw hex may appear outside `app/globals.css`. The only exceptions are `app/icon.svg` and `app/opengraph-image.tsx`, which use the dark-theme token values as literal hex because the stylesheet never reaches them.
## Content and components

- All case study content lives in `content/case-studies/` as `.mdx` files, one file per case study. Nothing else reads or writes that directory.
- Every case study file starts with YAML frontmatter matching `CaseStudyFrontmatter` in `lib/content.ts`: `slug` (string), `title` (string), `subtitle` (string), `kind` ("featured" or "library"), `order` (number), `badges` (array of strings), `metricStrip` (string or null), `summary` (string), `disclaimer` (string or null). Every field is required; the two nullable fields take an explicit `null` when they do not apply. A `disclaimer` may contain `[text](https://...)` links, rendered as links by the case study page; links in a case study body (and in the disclaimer) follow TextLink's rule through the page's `a` mapping, so other sites open in a new tab with a hidden warning. The one exception is `liveUrl` (an absolute `https://` URL, or null): optional, for a product that is publicly usable, and treated as null when absent. When set, the work card shows a "Live" pill and the masthead a "Try it live" link. `liveNote` (a non-empty string, or null) is optional too: a short note shown in faint sans directly under the masthead's "Try it live" link, only when `liveUrl` is set. The Live pill is the one place a pill uses the accent; every other pill stays in `--border` and `--text-muted`. `method` (a non-empty string, or null) is likewise optional and treated as null when absent. A library study with a `method` gets a flipping card: the work card turns over (`rotateY`) on hover and keyboard focus to show it. That flip is the only rotation and the only 3D transform on the site, confined to `WorkCard` and the `[data-flip-*]` rules in `app/globals.css`, and it must stay inside `@media (hover: hover)` with the reduced-motion handling (no rotation; the back face appears instantly). The timeline's `scaleY` draw-in and the scroll progress bar's `scaleX` fill are the only other transforms. Featured cards and cards without `method` never flip. `validateFrontmatter` throws at build time on anything else, naming the file and the field. `readingMinutes` is derived, never authored: `lib/content.ts` computes it from the body at build time (`countReadingWords`, at `READING_WORDS_PER_MINUTE` = 220, rounded, minimum 1, with JSX tags and their attributes excluded), the work card's front face shows it as an out-of-flow chip in its top-right corner (a one-line float at the start of the heading keeps the first line clear of it), and a file that sets it fails the build.
- Case studies are loaded through `getAllCaseStudies` and `getCaseStudyBySlug` in `lib/content.ts`, sorted by `order`, and rendered by the static route `app/work/[slug]/page.tsx`.
- Homepage copy lives in `content/homepage.json`, loaded and validated by `getHomepageContent` in `lib/homepage.ts`. Homepage work cards derive from case study frontmatter (`kind: "featured"`) and are never duplicated into `homepage.json`: no case study title, subtitle, summary, badge or metric strip appears there. The homepage sections live in `components/home/` and are all server components.
- `/work` (`app/work/page.tsx`) lists both tiers, featured then library, each in `order`; its copy lives in `content/work.json`, validated by `lib/work-index.ts`. The work card (`components/WorkCard.tsx`) is shared between the homepage and `/work`; change it once, not per page.
- The content components are a fixed set of seven: `Confidence`, `MetricStrip`, `ContentTable`, `Callout`, `ArticleHeading`, `BeforeAfter` and `Screen`. Do not add an eighth, and do not extend or split these seven, without explicit approval. Six are server components, `Screen` among them: no `useState`, no `useEffect`, no client hooks. `BeforeAfter` is the exception: a client component, for its toggle state. `Screen` and `BeforeAfter` share one frame treatment, the class constants in `components/image-frame.ts`; change the frame there, not in either component. The chrome components are `SiteHeader`, `SectionIndex`, `ThemeToggle` and `CaseStudyBar`, all client components. With `BeforeAfter`, `GridParallax` (which renders nothing and drifts the background grid with the cursor, on hover-capable devices without reduced motion) and `Reveal` (which renders nothing and runs the site's one entrance-reveal observer) they are the project's only seven client components. Do not add an eighth without explicit approval. `SiteHeader` shows the same pill on every route: home mark, the seven homepage section links (`#id` on `/`, `/#id` elsewhere) and the theme toggle. `SectionIndex` and the homepage nav share their scroll tracking through `useActiveSection` in `lib/use-active-section.ts`. The nav calls it only on `/`.
- Case study images live in `public/images/<slug>/` and must have descriptive alt text.
- `/certificates` (`app/certificates/page.tsx`) lists every certificate: the homepage's credential cards, read from `certifications` in `content/homepage.json`, then an "Also completed" list whose copy lives in `content/certificates.json`, validated by `lib/certificates.ts`. Both share the credential rules in `lib/credentials.ts` (link label exactly "Verify credential" or "View certificate", link an `https://` URL or a `/certificates/` file, card span 4 to 8). Credential cards render through `components/home/CredentialCard.tsx`, shared by both pages. Issuer logos live in `public/images/certs/` and certificate files (PDF and JPG) in `public/certificates/`. No dates on credentials. Every card stacks its logo above its text at every width; its span sets grid width only. Each card states its `logoSize` ("base" 64px, "md" 76px or "lg" 88px). The `/certificates` masthead carries a back control, a plain `next/link` to `/#certifications` with its label and href in `content/certificates.json`; it never touches browser back. Below "Also completed", an `archive` link (label and `https://` href in `content/certificates.json`) opens the full Drive folder in a new tab.
- Icons are permitted only in `components/icons.tsx`, and only as hand-written inline SVG: no icon library, no icon font, no image files. The set is the home mark, sun and moon, four contact marks - `MailIcon`, `LinkedInIcon`, `GitHubIcon` and `FileIcon` - `ExternalLinkIcon` for the masthead's live link, credential links and the /certificates archive link, `FolderIcon` and `FoldersIcon` for the hero's "View work" and the "All work" link, `AwardIcon` for the homepage's "More certificates" link, `ArrowLeftIcon` for the back control on `/certificates`, and `ClockIcon` for the work card's reading time, all drawn as simple line marks, never copied brand logos. Icon links on the homepage (hero actions, "All work", contact row) go through `components/home/IconLink.tsx`.
- The homepage contact form is a plain HTML `<form method="POST">` to the Formspree endpoint in `content/homepage.json`. It has no client code and must keep working with JavaScript disabled.
- Scroll-linked effects (the timeline draw-in, the progress bar) are CSS scroll-driven animations in `app/globals.css`, inside `@supports` and `@media (prefers-reduced-motion: no-preference)`. Entrance reveals are the one exception that uses JavaScript: `components/Reveal.tsx` runs a single IntersectionObserver for the whole site over `[data-reveal]` (homepage section children, and case study article block children, which it tags at runtime). Content is visible by default; only elements the component has marked `pending` are hidden, and only under `prefers-reduced-motion: no-preference`, so without JavaScript or with reduced motion everything shows. Never add a second observer or a per-element one, and never reveal the hero.
- Route changes cross-fade through React's `<ViewTransition>`, wrapped in each `page.tsx` (`enter`/`exit` `page-fade`, `default="none"`), with the timing in `app/globals.css`: opacity only, 200ms, off under reduced motion. The header keeps `view-transition-name: site-header` so it never fades or gets drawn over. It needs no `next.config` flag. `data-scroll-behavior="smooth"` stays on `<html>`, so smooth scrolling stays off during route changes.
